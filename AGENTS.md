# AGENTS.md — Repository Architecture for Coding Agents

This document describes the structure, conventions, and rules of the Geometry of Meaning repository. It is written for coding agents (Codex, Claude, etc.) working inside this codebase. Follow these rules strictly.

## Repository Architecture

The repository mirrors the research hierarchy across three directory trees:

```
experiments/<research_area>/<experiment>/   ← protocol definition
data/variants/<research_area>/<experiment>/  ← generated textual variants
runs/<research_area>/<experiment>/           ← numerical run results
```

These represent three stages of the same experiment pipeline:

```
experiment definition → generated variants → numerical results
```

### Directory Map

| Path | Purpose | Editable? |
|------|---------|-----------|
| `data/texts/originals/` | Stable canonical source texts | Manual only |
| `data/texts/translations/` | Canonical translations by language | Manual only |
| `data/texts/metadata/` | Corpus metadata (JSONL) | Manual only |
| `data/variants/` | Generated experimental texts | Generated by experiments |
| `experiments/` | Experiment definitions, configs, scripts | Manual + code |
| `runs/` | Immutable run outputs | Generated by experiments |
| `src/geometry_of_meaning/` | Reusable library code | Manual + code |
| `scripts/` | Repository-wide utilities | Manual + code |
| `tests/` | Test suite | Manual + code |

## Repository Skills

Before performing one of the following standardized operations, **read and follow the matching repository skill.** Each skill encodes the repository conventions into a concrete, step-by-step workflow.

| Task | Skill file |
|---|---|
| Creating a new experiment | `.agents/skills/create-experiment/SKILL.md` |
| Adding a canonical source passage | `.agents/skills/add-corpus-text/SKILL.md` |
| Adding or updating canonical translations | `.agents/skills/add-translation/SKILL.md` |
| Generating experimental textual variants | `.agents/skills/generate-variants/SKILL.md` |

**Rules for using skills:**

- **Read the SKILL.md first.** Do not start the task before reading the full skill file.
- **Do not invent an alternative workflow when a matching skill exists.** The skill encodes repository conventions that take precedence over improvisation.
- **Extend the current structure; do not create parallel systems.** Follow existing naming, schemas, and directory layouts.
- **A task may require multiple skills.** For example, adding a new corpus passage and translating it requires reading both `add-corpus-text` and `add-translation`, then executing them in sequence.
- **Existing repository conventions take precedence.** If a skill and `AGENTS.md` appear to conflict, `AGENTS.md` and the actual repository structure are authoritative. Report the conflict.

Skills are stored as Markdown files under `.agents/skills/<skill-name>/SKILL.md`. See `.agents/README.md` for a summary.

## Critical Rules

### Reusable logic

**Do not place reusable logic inside experiment scripts.** If two experiments might need the same functionality, it belongs in `src/geometry_of_meaning/`. Experiment scripts (`validate.py`, `analyze.py`) should be thin orchestrators that call shared library functions.

### Immutable runs

**Do not overwrite existing runs.** Every execution creates a new timestamped directory under `runs/`. A change in configuration, prompt, model, code, or dataset produces a new run. If you need to re-run an experiment, create a new run directory.

### Variant provenance

**Every generated variant must reference its source text.** Variant records must include `text_id` (pointing to the canonical original) and `variant_id` (a unique identifier). The relationship chain must be traceable: original → translation → variant.

### Experiment completeness

**Every experiment must have a README and configuration file.** The minimum required files for an experiment are:

```
experiments/<area>/<experiment>/
├── README.md          ← scientific protocol
├── config.yaml        ← experimental variables
├── dataset.jsonl      ← text selection
├── prompts/           ← generation/evaluation prompts
├── validate.py        ← variant validation
└── analyze.py         ← numerical analysis
```

### Languages and models are variables, not directories

**Do not create language-specific or model-specific directories.** Language and embedding model are experimental variables configured in `config.yaml` and stored as columns in result tables. They are not directory categories.

### Prompts are version-controlled

**Prompts belong in files, not in Python strings.** Every prompt used for generation or evaluation must live in a `.md` file under the experiment's `prompts/` directory. Prompts are part of the experimental method and must be version-controlled, readable, and recorded in run manifests.

## Naming Conventions

### Text IDs

Use `snake_case` identifiers derived from the source work and key content:

```
pride_and_prejudice_opening
hamlet_to_be_or_not_to_be
einstein_relativity_extract
```

### Variant IDs

Construct variant IDs from the text ID, language, and key experimental parameters:

```
pride_it_100    (Pride and Prejudice, Italian, compression level 1.00)
pride_it_075    (Pride and Prejudice, Italian, compression level 0.75)
```

### Run directories

Use ISO 8601 timestamps as directory names:

```
2026-08-04T135700
2026-08-05T101200
```

### Language codes

Use ISO 639-1 two-letter codes: `en`, `it`, `zh`, `ja`, `da`.

## Data Formats

### Original text records

Each original text is a folder under `data/texts/originals/<text_id>/` containing two files:

- `source.txt` — the exact canonical passage (verbatim, no metadata)
- `metadata.json` — all metadata fields (no `text` field)

Example `metadata.json`:

```json
{
  "text_id": "pride_and_prejudice_opening",
  "title": "Pride and Prejudice opening",
  "author": "Jane Austen",
  "category": "novel",
  "original_language": "en",
  "source": "Pride and Prejudice, first edition, T. Egerton, London, 1813",
  "copyright": "public_domain"
}
```

Example `source.txt` (exact text only, no JSON wrapper):

```text
It is a truth universally acknowledged, that a single man in possession of a good fortune, must be in want of a wife.

However little known the feelings or views of such a man may be on his first entering a neighbourhood...
```

### Translation records (JSON)

```json
{
  "text_id": "pride_and_prejudice_opening",
  "language": "it",
  "source_language": "en",
  "text": "È una verità universalmente riconosciuta...",
  "translation_method": "human_reviewed_model_translation"
}
```

### Variant records (JSONL)

```jsonl
{"variant_id":"pride_it_100","text_id":"pride_and_prejudice_opening","language":"it","compression_level":1.0,"text":"..."}
{"variant_id":"pride_it_075","text_id":"pride_and_prejudice_opening","language":"it","compression_level":0.75,"text":"..."}
```

### Run manifest (YAML)

```yaml
run_id: 2026-08-04T135700
experiment: progressive_compression
research_area: semantic_preservation
languages: [en, it, zh, ja, da]
embedding_models: [multilingual-e5-large]
git_commit: abc1234
random_seed: 42
created_at: 2026-08-04T13:57:00+02:00
```

### Metrics table (Parquet)

A flat table where each row is one measurement:

```
text_id | language | model | compression_level | cosine_similarity | step_displacement | cumulative_trajectory_length
```

## How Experiments Are Structured

An experiment follows this pipeline:

1. **Load canonical texts** from `data/texts/originals/` and `data/texts/translations/`
2. **Read configuration** from `config.yaml` and `dataset.jsonl`
3. **Generate variants** (via subagents, writing to `data/variants/`)
4. **Validate** generated records with `validate.py`
5. **Write variants** to the mirrored path under `data/variants/`
6. **Embed texts** using shared code from `src/geometry_of_meaning/embeddings.py`
7. **Calculate metrics** using shared code from `src/geometry_of_meaning/metrics.py`
8. **Save results** as a new immutable run under `runs/`

## How Data Should Be Stored

- **Canonical texts** (`data/texts/`) are stable and manually curated. Experiments read from them but never write to them.
- **Variants** (`data/variants/`) are generated by experiment scripts. Organized by research area and experiment, mirroring `experiments/`.
- **Runs** (`runs/`) are created by `analyze.py`. Each run is a timestamped directory containing:
  - `manifest.yaml` — run metadata
  - `config.snapshot.yaml` — frozen configuration
  - `dataset.snapshot.jsonl` — frozen dataset selection
  - `variants.manifest.jsonl` — reference to generated variants
  - `embeddings.parquet` — embedding vectors
  - `metrics.parquet` — computed metrics
  - `summary.json` — aggregate findings
  - `logs.txt` — execution log

## Generated Files That Must Not Be Manually Edited

- Anything under `data/variants/` (generated by experiments)
- Anything under `runs/` (immutable run outputs)
- Snapshot files within runs (`config.snapshot.yaml`, `dataset.snapshot.jsonl`)

## Reproducibility Rules

1. **Fixed random seeds** — every experiment must use and record a random seed.
2. **Config snapshots** — every run must capture the exact configuration used.
3. **Git commit recorded** — every run manifest must record the git commit hash.
4. **Prompt hashes** — every run manifest must record hashes of the prompts used.
5. **Model versions** — embedding model identifiers must include version information.
6. **Identical inputs + seeds → stable outputs** — the test suite should verify this.

## How to Validate Changes

Before finishing work on this repository, verify:

1. All text IDs are unique across `data/texts/originals/`
2. Every translation references an existing original via `text_id`
3. Every variant references an existing canonical text via `text_id`
4. All experiment directories have the required files (README.md, config.yaml, dataset.jsonl)
5. No run directories have been modified after creation
6. `pyproject.toml` is valid
7. All imports in `src/geometry_of_meaning/` resolve correctly
8. Experiment scripts import from `src/geometry_of_meaning/`, not from other experiments
9. No language-specific or model-specific directories exist under `data/`, `experiments/`, or `runs/`
10. No prompts are hardcoded as Python strings inside scripts
